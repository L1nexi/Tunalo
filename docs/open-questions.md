本轮结论已写入 [SPEC](SCENE_SELECTION_MODEL_SPEC.md)、[实施计划](SCENE_SELECTION_MODEL_IMPLEMENTATION_PLAN.md) 和[构建参数及规则表](SCENE_SELECTION_MODEL_DEFAULTS.md)。以下保留原问题编号用于追溯，不再作为待答问卷。内部初值和规则由实施者维护，不要求用户逐项定值。

## 本轮已关闭的问题

| 编号 | 结论及落实位置 |
| --- | --- |
| Q-01：边界与温度 | 不强制对称，初版正负边界均为 0.5；温度偏向探索。实施初值 `T_V=1.4`、`T_C=1.5`，算例及约束见规则表第 1 节。内部参数不进入用户设置。 |
| Q-02：活动窗口 | 固定 600 槽，约十分钟；每次原有采样推进一槽。始终按全窗口归一，未观察槽为 `x=0` 的 OTHER，启动逐渐建立显著度。不按实际时间补槽。 |
| Q-04：活动规则 | 产品内置，重新拟定常用应用和标题清单，见规则表第 3 节。旧用户规则和编辑入口直接删除，不导入或合并；原识别器及其优先级复用。 |
| Q-05：季节平台 | 每个季节在自身峰值前后各 10 日为 1。沿用既有四个日期峰值；相对季节为 -1、邻季初版为 0，平台之间 S 形过渡。 |
| Q-06：时段曲线 | 复用现有 Time 根据天气 API 日出日落计算峰值及虚拟时间的逻辑；无平台，直接 S 形过渡。 |
| Q-07：天气 | 按 OWM 具体代码逐项给值，允许中间强度，不限制为四档。晴朗与阴云中性，不推出雨的负值。55 个代码及雨雪混合、主分类回退均已列入规则表第 4 节。 |
| Q-08：配置 | 允许 breaking change，旧格式不支持、不转换。新版只保留新契约，继续使用 ProfileStore 和 ProfileManager 的原保存、验证及应用流程。 |
| Q-09：名称与场景 | 沿用 `dawn/day/sunset/night` 以及既有 Time 名称；保留 `focus/chill` 和十个 SceneId。Scene 使用直接情境的等地位关联，具体集合见规则表第 5 节。 |
| Q-10：调度接入 | 停用旧连续性并删除无用代码，只作最小适配。保留集合相等判断、控制门槛和执行时抽样，实际执行使用本次 Scene 分布；不设计新调度模型。 |
| Q-13：模块名称与划分 | Matcher 更名为 Selector，公开方法为 `select(context)`；继续持有并调用 Policy，不拆出 Observer。语义状态仍由 Policy 持有，Selector 继续代理状态导入导出；Engine 在采集后调用 Selector，实际抽样仍在执行边界。 |

## 已由现有代码回答的事项

- Q-03（缺失、错误与缓存）：复用空窗口、未命中零即时方向、天气无数据无贡献、请求失败保留缓存及 Context 异常保留原字段。不存在重新设计一套 Sensor 失败分类的要求。
- Q-11（状态归属）：ActivityPolicy 持有内存轨迹，暂停继续观察，停止不采样，进程重启从空状态开始；配置热替换通过已有状态导入导出承接。新轨迹采用相同生命周期，不转换旧 EMA。
- Q-12（诊断）：沿用 Tick History、Event Log、DTO 精度、导出和脱敏边界，只适配模型字段；不引入活动轨迹持久化。

代码依据见实施计划第 2.1 节。热替换时接续运行中状态，与支持旧配置格式是两件事；前者复用既有机制，后者已明确不做。
