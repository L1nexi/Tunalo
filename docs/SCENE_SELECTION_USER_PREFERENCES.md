# 问题一：用户偏好

更新：2026-10-06。状态：讨论进行中。共同边界与设计原则见[讨论总览](SCENE_SELECTION_MODEL_DISCUSSION.md)。

本问题讨论用户有哪些中长期偏好，以及产品允许用户怎样自然地表达这些偏好。

## 1. 粗粒度偏好

偏好面向天气、活动、时段、季节等上下文变量，例如希望壁纸跟随季节、当日时间或工作／娱乐。用户可以表达变量间的同等地位或先后关系，由产品负责转成选择行为。

“希望跟随季节”包含显著性条件：季节感明显时跟随季节，过渡期允许近似选择。

## 2. 级联选择

当前采用按偏好程度从高到低扫描的方向：

1. 查看当前偏好层级。
2. 该层有正向显著变量时，以这些变量关联的场景形成正向召回范围，停止向下扫描。
3. 该层没有正向显著变量时，继续下一层。
4. 所有已表达偏好都未提供正向显著变量时，回到不施加偏好优先级的选择。

单变量偏好是这一规则的特例。同层只有一个变量显著时，响应它；多个变量同时显著时，合并它们关联的场景。同层地位相同，仍可因当前显著程度不同而获得不同的选择概率。

偏好先确定正向召回来源，随后执行负向排除并分配概率，详见[场景选择与概率预算](SCENE_SELECTION_PROBABILITY_MODEL.md)。上下文整体无显著项时，进入尽力选择。

## 3. 负向意愿与配置一致性

独立的负向意愿表达仍待决定。变量全集已知时，“不希望跟随天气”可以通过偏好其他变量，或不启用天气相关场景来表达。

明确表达偏好却未启用相应场景，属于配置矛盾，可在配置层提醒。本轮召回或负向排除导致某变量没有候选，则属于运行时可用性问题。

上下文的负向显著度表达当前语义与场景的违和，独立于用户是否表达负向意愿。

## 4. 细粒度表达的价值与代价

粗粒度“活动”把工作、空闲、娱乐等内部项放在同一偏好地位。细分只有在内部项与其他变量具有不同偏好关系时，才提供额外选择信息，例如：

- 工作低于天气，天气低于娱乐。
- 白天低于工作，工作低于夜晚。
- 工作低于娱乐，娱乐等于天气。

仅表达工作低于娱乐，通常作用有限，因为这些内部项通常不会同时显著。

跨变量细分偏好属于长尾需求。从四个粗变量扩展到十余个内部项，会增加配置复杂度，并要求用户理解系统的内部分类。

## 5. 待讨论

- 级联偏好的具体交互表达。
- 是否提供独立的负向意愿表达。
- 是否支持细粒度偏好，以及是否混合粗细粒度。
- 偏好参与范围与变量预算的最终衔接。
