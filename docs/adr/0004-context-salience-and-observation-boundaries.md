# 用观测和有限活动轨迹构建独立的有符号显著度

场景选择需要知道雨、工作、白天、夏季分别有多明显，旧方向归一化和 Policy 权重会混合现实判断与响应偏好。决定由 Policy 从观测及必要轨迹构建每项有符号显著度，保留绝对大小，再交给 [ADR-0003](0003-scene-probability-budgets-and-preference-cascade.md) 的概率模型；语义不因偏好、启用场景、播单或播放状态改变。

## 共同标尺与构建边界

四个变量共用 14 个语义项：四季、`dawn/day/sunset/night`、晴朗／阴天／雨／雪，以及 `focus/chill` 表示的工作／娱乐。正值是支持，零是中性或无证据，负值是反向或违和。负向依据明确违和，不因分类不同就机械地互相排斥；同等明确的通常正向状态以 1 为共同参照，它不是上限，暴雨等更强状态可以超过 1。

构建先锚定感知明确的状态，再近似中间区域，显著边界不反过来塑造曲线。支持依据增强时显著度不下降，也不因状态持续、用户可能习惯而自动减弱。判断把握和显著程度不是同一概念，当前不另增统一的置信度维度。缺失观测沿用已有零证据和缓存回退，不额外建立一套统一缺失状态分类。

2026-10-13 修订：季节与时段采用覆盖完整支持轴的对称幂激活函数：

$$
F_\alpha(x)=\frac{(1+x)^\alpha-(1-x)^\alpha}{(1+x)^\alpha+(1-x)^\alpha},\qquad -1\le x\le1,\ \alpha>1
$$

函数保持正负对称、零点和 ±1 端点，中心斜率为 alpha，两端斜率为零；默认 alpha 为 2，季节与时段各自维护参数。它从最支持到最不支持走一条完整 S 曲线，中性位置处于曲线中部。这个决定取代先变形相邻区间进度、再插值输出的旧构造，也不采用正负各套一段激活函数的拼接。

`salience_activation` 负责完整支持轴上的激活；`periodic_salience` 负责将最短周期距离转换为支持依据；`time_decaying_activation` 复用激活函数形成 [0,1] 的年龄权重。活动净证据仍直接输出，天气仍按观测标尺构建强度，不统一封顶为 1。

## 活动：前台轨迹、固定槽位与净方向

只用前台应用身份、窗口标题及其近期分类轨迹判断工作或娱乐。完整桌面窗口池、普通后台进程、输入频率、媒体播放和系统会话未显示足够的独立收益，当前不加入活动主线。无输入可以是阅读或思考；有音频也不证明注意力。界面内容读取、截图和识别的投入与观察边界不适合当前目标。

每次现有采样推进一个槽位，保存最近 600 次分类观察，约对应十分钟；它取代早期讨论中的三十分钟时间窗。年龄按最新为 0、最旧为 599 的槽位次序计量，不按实际采样间隔重采样，也不在停止或休眠后补槽。固定槽位复用原轮询，避免为近似活动判断引入另一套采集时钟。

以工作为正，工作／娱乐／OTHER 的方向分别是 `1/-1/0`，年龄权重及净方向为：

$$
w(a)=\frac{1+F_2(\max(1-a/h,-1))}{2},\qquad
r=\frac{\sum_{a=0}^{599}w(a)x_a}{\sum_{a=0}^{599}w(a)}
$$

年龄尺度 h 默认为 300 槽：最新观察权重为 1，300 槽时为 0.5，600 槽及之后为零。实际窗口的年龄仍为 0～599，不另建活动 alpha 参数。

未观察槽和 OTHER 均按零参加全窗口分母，不按已识别数量重新归一。合成支持与反向证据后直接输出 `s_focus=r`、`s_chill=-r`。年龄加权已经平滑活动轨迹，不在其后再次套用显著度激活。一次明确观察不会成为满值；连续 600 次同方向覆盖整个窗口时达到 1。时间权重只看年龄，不叠加连续段奖励、短暂穿插状态或独立等待阈值。

用户活动规则只决定窗口如何被分类，不开放年龄权重或匹配数值。最终保留自定义进程与标题规则：未提供活动配置时使用产品默认规则；显式配置完全替换默认，空对象不识别活动，不合并两套规则。标题优先于进程，识别器保留已有匹配优先级与标准化。初步实施时删除用户规则的方案已撤回。

轨迹只保存工作／娱乐／OTHER 分类，不保存窗口标题和 Context 历史。OTHER 不表示空闲，不是可关联语义项，也不另建游移显著度。暂停仍采集，停止不采集，同一运行实例恢复可继续使用内存轨迹，进程重启从零开始；状态所有权与热替换见 [ADR-0005](0005-selection-and-scheduling-boundary.md)。

## 季节与时段：平台和真实昼夜锚点

对某项语义，以本位峰值 p 和周期 P 计算最短距离：`delta=abs(position-p)%P`、`d=min(delta,P-delta)`。令 H=P/2、平台半宽为 h：d≤h 时返回 +1，d≥H-h 时返回 −1，其余位置计算 `F_alpha((H-2d)/(H-2h))`。没有平台时即为 `F_alpha(1-2d/H)`；四分之一周期处为零，跨年和跨午夜闭合。

季节只使用当地日期、365 日周期及现有四季峰值。每项语义的本位和半周期相对位置各保留前后七日的平台。四季峰值不严格等间隔，邻季峰值允许弱正负证据，不强制为零，也不保留邻季零值平台。暂不把气温或日照融合成季节，邻季不机械地达到负向排除程度。

时段沿用天气 API 的日出、日落和昼夜中点，保留 `dawn/day/sunset/night`。把相邻真实峰值之间映射为六个虚拟小时，在 24 小时虚拟周期中按各项自己的峰值计算最短距离并激活，不设平台。真实峰值间距仍随昼夜长度变化。没有获得过有效日出日落时全零；本次缺数据而已有峰值时保留既有值，不另加固定钟点兜底。

## 天气：共享晴朗、阴天与降水关系

OWM 代码提供正向依据，Policy 统一推导晴朗、阴天、雨、雪的支持和反向关系。阴天表达没有降水、也不明显晴朗，不能因雨天云多就重复支持阴天。降水是雨雪的共同推导概念，不另成为预算来源。

- 晴朗与明显降水强反向；阴天与二者弱反向。
- 雨雪各保留自己的正向强度，混合时公共降水强度取 max，不重复增强对晴朗与阴天的反向证据。
- 降水对晴朗的强反向随强度变化，对阴天保持弱反向；初步实施将晴朗、阴云全部设零的方案已撤回。

降雨按小雨／中雨／大雨／暴雨为 `0.75/1/2/4` 的标尺校准，逐代码保留中间值。下雨本身已具有明显的情境显著度，因此小雨也从较高支持值开始；这次校准提高降雨标尺，雪仍沿用现有取值。数值是内部感知校准，不是 API 返回的显著度，也不宣称天气代码对应某一毫米降水阈值。当前使用代码、主分类和日出日落，不新增降水量、云量或额外请求。

雷暴本身是强烈的雨景情境，由雨语义承接。未明确标注降雨的雷暴仍提供强支持；伴随小雨或毛毛雨也不削弱雷暴本身的显著度。校准依据用户感受到的雷暴情境，不把雷暴等级机械等同于雨量等级。轻雷暴、普通雷暴、强雷暴的当前取值及逐代码映射见开发指引。

已知代码优先，即使结果全零也不按主分类重新解释；只有未知代码才回退主分类。没有观测或两者均未知时全零；请求失败继续解释已有 Sensor 缓存。具体公式、代码强度和默认值属于实现维护，见[开发指引](../DEVELOPMENT.md#天气共同推导)及 [WeatherPolicy](../../core/policies/weather.py)。
