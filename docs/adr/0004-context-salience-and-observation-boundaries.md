# ADR-0004：用观测和有限活动轨迹构建独立的有符号显著度

场景选择需要知道雨、工作、白天、夏季分别有多明显。决定由 Policy 从观测及必要轨迹构建每项有符号显著度，保留绝对大小，再交给 [ADR-0003](0003-scene-probability-budgets-and-preference-cascade.md) 的概率模型；语义独立于偏好、启用场景、播单或播放状态构建。

## 决策

### 标尺与构建边界

第一版设计中系统含 14 个语义项：四季、`dawn/day/sunset/night`、晴朗／阴天／雨／雪，以及 `work/leisure` 表示的工作／娱乐。正值是支持，零是中性或无证据，负值是反向或违和。负向依据明确违和。通常的正向显著状态峰值以 1 为共同参照。“通常”的含义是，某一变量达到“常见”的显著峰值的状态。因此 1 并不是上限，暴雨等更强状态可以超过 1。

从环境信息构建显著度时，优先锚定感知明确的状态，例如正向显著峰值、无证据和负向显著峰值，最后再近似中间区域。显著边界的设立独立于显著曲线。支持依据增强时显著度要求单调非减。

季节与时段采用覆盖完整支持轴的对称幂激活函数：

$$
F_\alpha(x)=\frac{(1+x)^\alpha-(1-x)^\alpha}{(1+x)^\alpha+(1-x)^\alpha},\qquad -1\le x\le1,\ \alpha>1
$$

函数保持正负对称、零点和 ±1 端点，中心斜率为 alpha，两端斜率为零；默认 alpha 为 2，季节与时段各自维护参数。它从最支持到最不支持走一条完整 S 曲线，中性位置处于曲线中部。

### 活动：前台轨迹、固定槽位与净方向

使用前台应用身份、窗口标题及近期轨迹判断工作或娱乐。完整桌面窗口池、普通后台进程、输入频率、媒体播放和系统会话未显示足够的独立收益，当前不加入活动主线。原因在于无输入既可以是放松阅读也可以是工作时思考，音频播放也同时兼容工作和娱乐。

每次现有采样推进一个槽位，保存最近 600 次分类观察，约对应十分钟。年龄按最新为 0、最旧为 599 的槽位次序计量，不按实际采样间隔重采样，也不在停止或休眠后补槽。

在活动语义的计算上，若以工作为正，则工作／娱乐／游移的方向分别是 `1/-1/0`，年龄权重及净方向为：

$$
w(a)=\frac{1+F_2(\max(1-a/h,-1))}{2},\qquad
r=\frac{\sum_{a=0}^{599}w(a)x_a}{\sum_{a=0}^{599}w(a)}
$$

年龄尺度 h 默认为 300 槽：最新观察权重为 1，300 槽时为 0.5，600 槽及之后为零。

未观察槽和游移均按零参加全窗口分母。合成支持与反向证据后直接输出活动显著度。

用户可以配置活动规则决定窗口如何被分类。系统按分类提供预设规则组，同时也需支持自定义进程与标题规则。未提供活动配置时使用产品默认规则。标题优先于进程，识别器保留已有匹配优先级与标准化。

轨迹用于保存最近一个窗口的活动情况，按工作／娱乐／游移分类，但不构建游移显著度或语义项。调度器暂停时保持采集，同一运行实例恢复可继续使用内存轨迹，进程重启从零开始。

### 季节与时段：平台和真实昼夜锚点

对某项语义，以本位峰值 p 和周期 P 计算最短距离：`delta=abs(position-p)%P`、`d=min(delta,P-delta)`。令 H=P/2、平台半宽为 h：d≤h 时返回 +1，d≥H-h 时返回 −1，其余位置计算 `F_alpha((H-2d)/(H-2h))`。没有平台时即为 `F_alpha(1-2d/H)`；四分之一周期处为零，跨年和跨午夜闭合。

季节使用当地日期、365 日周期及现有四季峰值。每项语义的本位和半周期相对位置各保留前后七日的平台。四季峰值不要求等间隔，邻季峰值允许弱正负证据。

时段使用本地计算的日出、日落和昼夜中点，保留 `dawn/day/sunset/night`。相邻真实峰值之间各映射为六个虚拟小时；在 24 小时虚拟周期中按各项自己的峰值计算最短距离并激活，不设平台。真实峰值间距仍随昼夜长度变化。

2026-10-29 修订日出日落来源：由 Sensor 按配置地点和系统当地日期在本地计算，经 Context 交给 TimePolicy；天气 Sensor 只提供气象观测，使启动与离线时的时段判断独立于天气服务。仅缓存天气 API 的日出日落仍依赖首次联网，并需要处理跨日后的旧数据，因此选择本地计算。数据契约、缓存规则与验收见[本地昼夜计算规格](../LOCAL_SUN_TIMES_SPEC.md)。

白天、夜晚是持续状态，黎明、夕阳是较短的事件。因此，白天、夜晚应该具备更宽的语义覆盖宽度，黎明、夕阳则用更窄的语义覆盖宽度。

### 天气：共享晴朗、阴天与降水关系

使用 OWM 数据获取依据。在 WeatherPolicy 中统一推导晴朗、阴天、雨、雪的支持和反向关系。阴天表示无降水的多云天气，与真实降雨的雨雪、大太阳的晴朗天气区分。

场景语义示例：

- 晴朗与明显降水强反向；阴天与二者弱反向或者中性。
- 雨雪各保留自己的正向强度，混合时公共降水强度取 max。

降雨按小雨／中雨／大雨／暴雨为 `0.75/1/2/4` 的标尺校准，逐代码保留中间值。下雨本身已具有明显的情境显著度，因此小雨也从较高支持值开始。当前使用天气代码和主分类，对降水量、云量等额外信息的使用处在概念构思阶段。

雷暴本身是强烈的雨景情境，由雨语义承接。未明确标注降雨、伴随小雨或毛毛雨的雷暴同样可以提供强支持。
