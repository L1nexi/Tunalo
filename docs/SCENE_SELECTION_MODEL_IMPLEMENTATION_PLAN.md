# 上下文语义与场景选择模型实施计划

日期：2026-10-09；更新：2026-10-10。状态：待实施；本轮问题已有结论。代码核对基线：`727c75f`。

规格入口：[SCENE_SELECTION_MODEL_SPEC.md](SCENE_SELECTION_MODEL_SPEC.md)。数值、应用规则、天气代码和 Scene 关联见[构建参数及规则表](SCENE_SELECTION_MODEL_DEFAULTS.md)，本轮决定见 [open-questions.md](open-questions.md)。现有代码已经表达的采集、回退和生命周期直接复用；主要重构语义与数值模型。

## 1. 目标与实施方式

主要修改 Sensor → Selector 路径：保留 Sensor 的采集流程，将 Matcher 更名为 Selector，公开入口为 `select(context)`。Selector 继续持有并调用 Policy，内部完成有符号显著度构建和场景概率计算，不拆出 Observer。移除旧标签权重、回退扩展、余弦匹配和候选池截断。本版所需窗口、日期与天气字段均已存在，不扩大 Sensor 接口。

按本次要求，**先完整实现，再集中调整和补充测试**。下文按依赖划分工作包，不采用“一条测试 → 最小实现”的逐片推进方式。实现阶段可以做类型、导入、格式和运行检查；行为测试的编写、旧测试调整和集中回归放在实现完成之后。

测试质量采用 tdd 技能的要求：通过公开接口验证行为，使用真实内部协作，只替换系统外部依赖；不测私有函数，不重复计算实现作为期望，不为字段透传补测试。

交付分为两个检查口径，不能相互代替：

- **模型完成**：观测与轨迹可构建显著度，Selector 满足 SPEC 的概率契约，配置能够表达相应输入。
- **产品接入完成**：Engine、调度消费、配置读写及诊断消费全部接通，旧规则不会改写新分布，应用能完整运行。调度只做第 4 节 E 中的最小适配。

本轮停用旧连续性，保留已有切换门槛和抽样时机，不设计新的调度模型。偏好在现有设置流程内表达层级即可；不借此重做整个界面。

以下是本次核对代码后确定的实施基线，不是等待用户重新选择的候选方案。只有与新模型发生具体冲突，才提出必要调整。

## 3. 目标职责与最小数据契约

保留现有 Sensor、Policy、Engine 的组合关系。Engine 创建四类 Policy 并注入 Selector；采集之后调用 `Selector.select(context)`，由 Selector 组织 Policy 求值、汇集显著度并计算完整场景概率分布。Policy 继续持有自己的语义状态，Selector 继续代理状态导入导出，不拆出 Observer，也不增加统一语义管理类。

调用顺序为 `Engine.schedule() → ContextManager.sense() → Selector.select(context)`；在 `select()` 内执行 `Policy.evaluate(context) → 汇集显著度 → 概率计算`。方法名中的选择表示形成选择概率，实际抽样仍在 Actuator 的执行边界。

| 接口 | 输入 | 输出与约束 |
| --- | --- | --- |
| 观测采集：`ContextManager.sense()` | 外部窗口、天气、当地时钟；其余控制观测沿用现有来源 | 沿用当前独立快照和失败回退；不输出工作、娱乐等推断结论 |
| 语义构建：Policy 的公开接口 | 观测、必要近期轨迹、产品构建参数 | 完整的语义显著度；诊断按实际用途适配，不强制公开中间量；不接收偏好、场景目录、当前 Scene 或播单大小 |
| 场景选择：`Selector.select(context)` | Context；Policy、偏好层级、可用场景关联及参数在构造时绑定 | 组织语义构建并返回 Scene 概率分布或空结果；每次新观测只推进一次活动轨迹，不采集、不抽样 |
| 概率计算：Selector 内部算法 | 显著度、偏好层级、可用场景关联、匹配参数 | 确定性的 Scene 概率分布或空结果；不推进语义状态 |
| 调度消费 | 匹配结果、调度状态 | 保留原门槛，执行时按当前分布选 Scene；抽样及状态提交不回流为显著度 |

需要一次性替换的数据含义：

1. **语义词表**：四个粗变量及其 14 个语义项，归属固定。保留 `dawn/day/sunset/night` 与 `focus/chill` 标识。Selector 不从启用场景反推语义空间；降水不增加第五份预算，OTHER 不进入场景关联词表。
2. **显著度**：每项一个有限有符号数值；保留负数和超过 1 的正数，不做上下文整体归一化。Policy 之间按语义归属汇集，不再把多个加权贡献相加。缺失天气与未命中活动规则按第 2.1 节承接，不增加统一缺失模型。
3. **场景关联**：每个场景一个非空、去重、等地位的语义集合。已启用且已绑定的场景才进入匹配。同播单的不同 Scene 继续保留身份。
4. **偏好**：有序层级，每层是同等地位的粗变量集合，显式层级中的变量不重复。无显式层级表示进入中立回退，不表示关闭所有变量。
5. **匹配结果**：按 SceneId 表示概率，非空分布总和为 1；没有可用或安全候选时返回明确空结果。评分、概率、采样结果是不同概念，不再复用 `similarity` 表达概率。
6. **构建参数与匹配参数**：产品维护的内部配置，与用户偏好分开。边界、温度、曲线参数、活动规则和天气观测映射不作为通用用户配置开放。

Selector 的场景输入只含它需要的场景身份和关联；Playlist 名称与数量留在配置和执行侧。这样可以从依赖关系上排除“播单大小改变选择概率”的可能。

### B. 重构 Selector 与概率计算

涉及：将 `core/runtime/matcher.py` 更名为 `core/runtime/selector.py`，清理 `core/runtime/tag_resolver.py`，调整选择输入和结果模型。

Selector 保留 Policy 调用和状态导入导出的代理职责，`select(context)` 先构建完整显著度，再按 SPEC 第 4.8～4.12 节执行以下确定性概率计算；这部分算法不读取 Context，也不推进 Policy 状态：

1. 用包含等号的正负边界形成显著项集合。
2. 在所有可用场景中统一排除含负向显著关联的场景，得到安全集合。
3. 分别为四个粗变量建立候选集；只有该变量正向显著的关联项可以召回场景。
4. 按显式层级依次查找有效来源。整层无显著来源或候选全空就继续；部分变量为空只移除这些变量，不引入低层。
5. 对层内变量取最高正向显著度，以 softmax 形成原始预算，忽略空变量后按比例归一。雨雪同属天气，取 max，不能相加。
6. 用完整显著度按 `sum(s_i) / sqrt(|A_c|)` 为场景评分；在各变量的候选集内分别 softmax，将条件分布按预算混合。
7. 显式层级穷尽后执行四变量中立层；仍无来源时，在安全集合中按同一评分与场景温度尽力选择。
8. 全零显著度产生均匀分布；安全集合为空产生空结果，不撤销排除。

计算要求：

- 不沿用 `PoolParams`、最低相似度、相邻分差、最大池大小或旧标签回退。
- softmax 使用数值稳定的计算方式；不对空集合归一化。有限输入、输出有限、概率非负及总和约束在公开接口上验证。
- 同一场景从多个来源得到的概率相加，但每份变量预算只能分配一次；场景评分不随来源或偏好层变化。
- 枚举或字典顺序不改变 Scene 对应的概率，Selector 不承诺返回项的固定顺序。展示排序由 DTO 处理，抽样所需的排列由执行侧处理；两者都不改写概率或截断候选。
- 原始计算保留精度；展示时沿用现有四舍五入。结果保留完整分布，诊断字段在现有 Trace 与 DTO 上做必要适配。

完成标志：`Selector.select(context)` 通过真实 Policy 输出完整分布；内部概率算法可以用给定显著度验证，不需要 Windows、网络或播放状态。直接输入显著度的调参工具复用同一概率算法，不复制实现；该入口的具体组织在实施时确定，不改变 `select(context)` 的运行时入口，也不为测试增加接口。

### C. 重构观测及语义构建

涉及：`core/policies/`、`configurations/runtime_models.py` 及其产品参数；Sensor 和天气解析继续提供已有字段。

**观测层与公共输出：**

- 复用 `Scheduler → Engine → ContextManager → Sensor.collect()`；每次新采样只计入活动历史一次，结果与诊断读取不推进历史。是否沿用 `evaluate()` 同时处理新观测并计算显著度，由实现决定，不固定方法调用次数或拆分方式。
- CPU、全屏、输入空闲仍只用于控制，不进入本版活动方向推断。窗口、天气及 Context 的原失败回退按第 2.1 节保留。
- 天气继续读取 `id/main/sunrise/sunset`，不增加请求或传感器字段；构造和配置验证仍不发起外部采集。
- 移除 `weight × salience × intensity × direction` 和方向归一化，Policy 直接输出每项有限的有符号显著度。替换旧 Evaluation 字段，不保留无意义的兼容字段。
- S 形映射和周期插值属于内部实现，不为每个步骤建立公共接口。

**活动：**

- 复用当前匹配器与标准化，规则换成构建参数表的应用／标题清单。命中工作为 `1`、娱乐为 `-1`，未命中及空窗口为 OTHER，即 `0`。
- ActivityPolicy 用最近 600 次观测的方向历史替换 EMA；未观察部分在计算中视为零，年龄按槽位序号，分母始终覆盖全部 600 槽。可采用有界队列，但不要求实际填满 600 个零，也不将容器类型作为验收条件。
- 先合成净方向，再经有符号 S 形映射，工作／娱乐反对称。权重与分母可以预计算；历史存储和计算保持有界，不保存整份 Context 或原始标题历史。缓存布局与遍历方式属于内部实现。
- 停止和休眠期间没有采样就不推进，不按实际时长补槽；暂停继续采样，进程重启全零，配置热替换接续已有分类槽位。
- 删除 EMA、旧平滑窗口与用户规则编译，不增加连续性奖励、短暂切换阈值或输入空闲推断。600 槽不是额外切换等待门槛。

**季节与时段：**

- 季节保留当地年内日期、365 日周期及四个既有峰值。四季各自峰值前后 10 日为正向平台，相对季节为负向平台，邻季中性，平台间 S 形过渡。
- TimePolicy 保留日出日落更新、昼夜中点计算、虚拟时间换算和原四个名称；只将 Hann 替换为连接 `1/0/-1` 锚点的 S 形曲线，不设置平台。
- 无初始日出日落则时段全零；已有峰值后缺失观测保留峰值。沿用天气缓存与分钟精度，不新增固定钟点兜底。

**天气：**

- 采用构建参数表中 55 个代码的逐项数值，允许中间强度及大于 1 的值；晴朗和阴云均为中性。
- 雨雪混合输出两项，预算层取 max；不凭云量重复支持阴云，不从晴朗推出雨的负值。
- 保留 `id → main` 回退，已知零值代码仍视为命中，只有未知代码才尝试主分类。没有数据或无法映射全零，请求失败仍使用已有缓存。

### D. 接通 Engine 与状态转移

涉及：`core/runtime/engine.py`、`profile_manager.py`、`core/policies/activity.py`。这里的状态转移只指正在运行的新模型配置替换，不涉及旧格式转换。

- Engine 在采集之后调用 `Selector.select(context)`，Policy 求值与显著度汇集留在 Selector 内；不增加 Observer 或新的统一语义管理类。
- `EngineReplacement` 持有 Selector，Policy 列表继续由 Selector 承接；Engine 通过 Selector 调用已有的状态导入导出入口。活动窗口继续由 ActivityPolicy 持有。
- 偏好、场景绑定等热更新接续分类后的 600 槽，新参数重新解释保留的方向；不恢复旧 EMA，不追溯重新识别原窗口。
- 沿用 `prepare_replacement → 持久化 → install_replacement` 顺序。准备失败不改变当前配置、历史和采集状态；状态快照与原对象隔离。
- Profile 更新仍只由调度线程在 tick 之间应用。Policy、Sensor、Selector 不读取 Profile，也不绕过应用队列。
- 沿用 Sensor 重建和 WeatherSensor 空缓存行为；TimePolicy 的峰值仍按已有生命周期重建。Tick History 只保存本次构建摘要。

### E. 完成最小接入并删除旧路径

整体接入完成后再集中编写测试，不保留两套匹配模型。

**调度只作以下适配：**

1. 从新分布取得具有正概率的 Scene 身份集合。Controller 保留原来的集合相等判断：与当前集合相同则 `CYCLE`，不同则 `SWITCH`；删去 `weighted_jaccard`、连续性衰减、阈值和对应状态。相等判断只决定沿用哪个既有门槛，不对分布重新打分。
2. `Decision` 传递本次完整分布。`SWITCH` 和 `CYCLE` 都在 Actuator 真正执行时按该分布抽取 Scene，再查绑定的 Playlist；删除按播单大小抽样，不合并同播单的 Scene，不取概率最大者。
3. 候选集合相同而概率改变时，仍沿用轮换门槛；下一次允许执行时使用最新概率。不增加概率距离阈值、每 tick 重抽或新的连续性算法。
4. 暂停、CPU／全屏阻塞、启动等待、空闲要求及轮换冷却保持现有语义；手动应用与恢复保留原有绕过门槛方式，并使用本次分布。阻塞和暂停不抽样；空分布仍保持已有播放或无动作。
5. `cached_scenes` 继续保存现有含义的场景集合，成功 `SWITCH` 后更新，执行失败不提交；不改成抽中 Scene 的单项缓存，不持久化概率。`plan_actuation` 对实际 Playlist 的反查逻辑保留。

这里暂不响应“同集合内概率改变应否立刻切换”之类后续调度问题。这是用户要求的最小接线，不能在本轮加出另一套调度模型。删除已经无调用方的连续性实现；必要时只留一行停用原因注释，不保留整段死代码。

| 接入处 | 必要工作 |
| --- | --- |
| Profile、本地 API 与编译器 | 新版层级读写、校验和错误提示；不支持旧格式，不做转换；保留唯一应用队列 |
| 场景目录与文案 | 沿用十个 SceneId 和名称，采用规则表中的直接情境关联；沿用 Time 名称 |
| 活动设置 | 删除 `ActivityProfile`、用户规则编译、`ActivityRulesStep.vue`、无调用方的 `ActivityListInput.vue` 以及对应表单状态、摘要、校验与翻译 |
| 偏好设置 | 更新 `frontend/src/api/profile.ts`、`setup/model.ts` 及现有设置／确认页面：按高到低列出偏好层，每层可选多个变量；支持层顺序调整与删除，变量不可重复；空列表表示中立 |
| 执行模型 | Match 表达概率，Decision 携带当前执行分布；Scenes 只保留身份、播单查找及反查所需能力，删除播单大小选择路径 |
