# 后续小版本待办

## Open

- [ ] **多显示器支持**
  - 功能描述：针对多显示器下的典型使用场景进行调研，对应分析调度设计和组织。
  - 优先级：P1
  - 理由：系统现有设计针对单显示器，而现在多显示器的需求逐渐增长。此外，多显示器用户有更多机会看到桌面，因此是有价值的 feature。需要对多显示器的使用场景进行调研。举例来说，需要知道"复制单个壁纸"、“拉伸单个壁纸”、“不同显示器的壁纸”的行为差异，如何区分，以及如何让调度器在多显示器下更好地工作。

- [ ] **评估多屏共同调度**
  - 功能描述：沿用现有场景和偏好，让多块屏幕共同呈现当下情境；研究保留各屏原有选择概率的协同选择方式。
  - 优先级：P1
  - 理由：同上

- [ ] **利用更多 OWM 观测字段**
  - 功能描述：评估降雨降雪量、云量等是否能改善显著度，以及季节判断是否需要加入温度。当前天气判断只使用天气代码和主分类。
  - 优先级：P2
  - 理由：可以将 OWM 观测字段用于季节、时段、天气的显著度构建，但是收益可能不显著。后续优化时考虑

- [ ] **评估独立音频响应语义**
  - 功能描述：当前音频不参与工作／娱乐判断。先判断是否有值得响应、可关联到场景的音频情境，再决定采集什么、如何表达。
  - 优先级：P3
  - 理由：工程量中小，但是需要评估这一块的需求。

- [ ] **重构日志与历史记录**
  - 功能描述：梳理运行日志、动作事件和 Tick History 的职责与数据传递，减少仅为填充记录字段而增加的多层属性转发。记录侧继续消费调度结果。
  - 优先级：P2
  - 理由：需要评估现有日志、记录的价值和必要性

## In Progress

- [ ] **本地昼夜计算**
  - 功能描述：利用已配置的地点和系统当地日期，在本地计算日出日落，让启动及离线时的昼夜判断独立于天气服务。范围见[行为规格](LOCAL_SUN_TIMES_SPEC.md)。
  - 优先级：P1
  - 理由：本地计算可直接提供当天锚点，按日期保留内存结果即可。
  - 状态：已实现，测试通过，待用户验收。

## Completed

- [x] **保留最大化状态**：聚焦时仅还原最小化窗口。
- [x] **即时保存外观偏好**：通过 pywebview 原生桥接独立保存到 `data/appearance.json`，关闭前等待保存完成；浏览器开发环境继续用本地存储。

## Denied

- [ ] **评估细粒度偏好与独立负向意愿**：当前只支持四个粗变量的层级；工作与娱乐、白天与夜晚之间的跨变量细分，以及“不希望响应某项”的独立表达仍未决定。

## Postponed
