# 问题三：上下文语义与显著度

> 2026-10-09 补充：下文保留原讨论过程。实施以最新 [SPEC](SCENE_SELECTION_MODEL_SPEC.md)、[实施计划](SCENE_SELECTION_MODEL_IMPLEMENTATION_PLAN.md) 和[构建参数及规则表](SCENE_SELECTION_MODEL_DEFAULTS.md) 为准：活动改为 600 槽；时段复用 API 日出日落及旧名称，不设平台；天气逐代码给值，晴朗／阴云中性；旧配置不兼容，调度停用连续性并作最小适配。下文旧参数、旧例子和“待落实”不再直接构成当前实施要求。

更新：2026-10-07。状态：已确认构建主干整理为[规格](SCENE_SELECTION_MODEL_SPEC.md)，参数与观测映射待落实。共同边界与设计原则见[讨论总览](SCENE_SELECTION_MODEL_DISCUSSION.md)。

本问题讨论怎样从原始观测构建雨、夜晚、工作等场景语义，使其能用于[变量预算和场景选择](SCENE_SELECTION_PROBABILITY_MODEL.md)。活动构建主干、季节与时段的显著平台加 S 形过渡结构，以及天气强度标尺已确定；锚点位置、函数参数、观测数据到等级的对应及跨变量校准仍待落实。本记录区分已确认方向和开放项，不是完整实现规格。

## 1. 现实锚定与数值表达

构建函数需要同时回答两个问题：

1. **现实感官锚定：**哪些现实状态或测量信息支持该语义，例如季节感、日内时间感、降雨量、持续活动？
2. **数值表达形式：**如何把这些依据映射为显著度，包括曲线、范围、连续性、不变量和尺度？

先锚定感知明确的状态，再近似中间区间。数值函数的选择应有现实依据。

### 构建函数的性质要求

| 性质 | 含义 |
| --- | --- |
| 跨变量可比较 | 不同上下文的显著程度能进入同一选择系统比较；这是最关键、也最难的要求。 |
| 保留绝对值 | 保留语义本身有多明显的信息，供尽力选择与候选比较使用。 |
| 独立于偏好和场景目录 | 语义由观测构建，包括理解当前活动所需的近期轨迹；用户偏好、场景数量和关联分布不改变语义值。 |
| 单调非减 | 其他相关条件不变，支持某语义的依据增强时，该语义的显著度不下降。 |

天气、活动、时段、季节可以使用不同的构建方式。

## 2. 有符号显著度与共同锚点

- 正向表示当前上下文对语义的支持。
- 零点表示语义中性或不存在。
- 负向表示反向关系；达到负向显著时，用于排除关联场景。

正负显著边界在曲线建模之后确定，显著不等于数值只要大于或小于零。

### 三类锚点

当前先寻找通常最显著的正向状态、零点和反向最显著状态。探索示例如下：

| 语义项 | 正向锚点示例 | 零点示例 | 反向锚点示例 |
| --- | --- | --- | --- |
| 夏季 | 夏季峰值日期前后各 10 天的正向峰值平台 | 春秋区域中性，也允许轻微负向 | 冬季的反向峰值平台 |
| 午夜 | 四时段均匀布置中的午夜锚点，具体钟点待定 | 待讨论 | 与午夜锚点相隔 12 小时的位置 |
| 工作 | 一段时间持续工作 | 时间加权净方向为零，构造见第 5 节 | 一段时间持续娱乐 |
| 雨 | 大雨对应 1，雨量等级标尺见第 4 节 | 最初以阴天／多云举例 | 大晴天 |

各变量通常最显著的正向锚点暂以 1 作为共同参照。它允许更强状态超过，例如暴雨可以大于 1。这样从感官语义较明确的一端建立跨变量校准，再近似中间部分。

活动已采用工作与娱乐的反对称构造，具体公式见第 5 节。其他变量的锚点对应、负向范围、正负是否对称，以及变量内各语义项是否满足总和约束，仍待讨论。

### 负向依据明显违和

夏季与冬季有明确的反向关系；春夏之交的春季则未必违和。负向取决于感知上的违和，分类不同或另一个语义更贴切都不足以推出负向显著。

盛夏时，春季和秋季可以中性或轻微负向，但不达到负向显著的排除程度；冬季则具有明确反向关系，应进入排除。相邻季节在其他周期位置的具体曲线仍待构造。晴朗／阴云／降水的当前语义边界见第 4 节，雨雪的具体关系仍待讨论。工作与娱乐的反向关系及其有符号数值构造已确认，见第 5 节。已确认的晴朗与雨、夏季与冬季的违和实例见问题二。

### 先建曲线，再定边界

显著度曲线先由感知依据构建，再讨论显著性边界 \(b\)。感知中的阈值效应描述上升速度变化，与召回的硬边界是两件事。

曲线连续性、正负边界是否对称仍待讨论。问题二当前采用的方向投影评分不使用独立的评分交接点 \(a\)。

### 显著度与判断把握

可以很确定正在下小雨，同时给出低显著度；活动则需要合成一段时间的观测。判断把握与显著度有区别，但用户质疑把握程度作为统一独立维度的价值。

活动中，未知的有方向活动与无方向活动难以仅凭观察区分。当前采用内部状态 Wandering（中文暂称“游移”），主要表达缺少持续主导方向，也近似容纳少量未识别的有方向活动；不向用户开放关联，不单独构建显著度。其他变量的信息缺失、无法判断、语义不存在与成立但不显著是否需要分别表示，仍待讨论。

## 3. 时段与季节的曲线方向

季节采用春、夏、秋、冬，现阶段仅以日期构建输入，不纳入温度或日照。时段采用白天、黄昏、午夜、凌晨，在当地钟点的 24 小时周期中均匀布置，相邻语义位置相距 6 小时，主要表达时段；当前不跟随日出日落。四时段整体对齐哪些具体钟点，仍待确定。

此前的非正式访谈启发了感官锚定和阈值效应的讨论：夏季感可以来自海边经历，冬季感也受凉到冷等变化影响。当前构建仍按上述范围，仅采用日期和钟点。

已确认季节与时段的周期函数采用显著平台加 S 形过渡：在感官语义最明确的区间保持峰值，在区间之间表达先缓、再快、再缓的变化。采用共用的三次幂指数映射原型作为过渡曲线。

支持依据增强时，显著度保持单调非减；仅因习惯而回落的方案未被接受。快速上升可以用连续曲线表达。

### 显著平台与周期过渡

以夏季语义为例：

- 夏季峰值日期向前、向后各 10 天，显著度稳定在正向峰值。
- 冬季区域具有稳定的反向显著度峰值。
- 春秋处于中性或轻微负向，不达到负向显著的排除程度。
- 平台之间主要通过 S 形曲线过渡，并在全年周期内闭合。

正向与反向通常峰值沿用共同参照的 1 与 -1。季节可复用这一周期构造；峰值日期、各平台和过渡区间的具体定位仍待落实。

时段采用同样的平台与 S 形过渡结构，在 24 小时周期中均匀布置四个语义项。日内峰值钟点与平台宽度仍待确定，不直接把季节的 10 天宽度用于时段。

### 共用的 S 形显著度映射原型

对已校准到 \([0,1]\) 的正向输入 \(z\)，采用：

\[
f_q(z)=
\frac{1-2^{-(z/q)^3}}
{1-2^{-(1/q)^3}},
\qquad q>0
\]

该函数单调非减，满足 \(f_q(0)=0\)、\(f_q(1)=1\)。分母保留归一化端点，\(q\) 控制感知阈值效应的曲线形状；固定三次幂后，平台和过渡宽度随参数联动。

这一归一化函数可作为平台之间的过渡核。对某个过渡区间 \([t_a,t_b]\)，两端显著度为 \(v_a,v_b\)，一种直接的构造表达是：

\[
u=\frac{t-t_a}{t_b-t_a},
\qquad
s(t)=v_a+(v_b-v_a)f_q(u),
\qquad 0\le u\le1
\]

平台内保持常值；上升或下降由两端值决定。这里的 S 形核用于周期曲线的区间过渡，不要求在已经构成的显著度曲线上重复套一次映射。

共用的是函数结构。日期、钟点对应的平台和过渡位置，以及各变量的参数值，仍待落实。采用同一曲线族本身不等于已完成跨变量校准。

此映射在活动中的有符号扩展见第 5 节。天气仍保留第 4 节的强度锚定方向；这里不将全部变量的显著度统一封顶为 1。

## 4. 天气数据与语义

### 数据来源

当前选择以 OpenWeatherMap（OWM）为主。此前考虑过 Open-Meteo 免 API Key、遇到公网 IP 共享限制再补 OWM；查阅文档后转向 OWM，理由是文档与现有信息更适合当前工作。和风天气的国内可达性曾被考虑，但本次注册体验和接入方式不适合独立桌面工具的需求。

接口事实见[OpenWeather 当前天气 API](archived/reference/OPENWEATHER_CURRENT_API.md)：

| 数据 | 语义用途 |
| --- | --- |
| 天气现象与代码 | 支持晴朗、阴云、降水及细分现象判断 |
| 降雨量、降雪降水量 | 支持降水强度锚定 |
| 气温、体感温度 | 曾讨论可辅助季节，当前暂不纳入；`temp_min/max` 表示当前温度范围，详见参考文档 |
| 日出、日落 | 曾讨论可辅助时段，当前暂不纳入 |

这些字段保留为数据能力参考；当前季节与时段按日期和钟点构建。

### 降雨强度锚定

天气显著度锚定相应物理强度。已确认按小雨、中雨、大雨、暴雨的雨量近似倍增关系采用以下降雨显著度分配：

| 降雨等级 | 显著度 |
| --- | --- |
| 小雨 | 0.25 |
| 中雨 | 0.5 |
| 大雨 | 1.0 |
| 暴雨 | 2.0 |

这四档是当前已确认的等级到显著度映射，不再仅作为曲线方向的示意，也不再经过把结果封顶为 1 的统一映射。其他天气强度同样从相应可观察物理量锚定，并参考其等级量级建立显著度。

这不等于为每一种天气现象机械复用同一组雨量阈值。供应商观测到等级的对应、累计时段与字段单位、其他现象的具体等级，以及是否需要档间连续近似，属于后续数据对应与细化工作。

### 晴朗、阴云、降水与雨雪

当前认可保留晴朗、阴云，并以降水组织共同语义，内部区分雨和雪。层次组织用于共享推导，减少为每个语义项独立映射全部天气代码的复杂度。

阴云（阴天）表达没有降水、也不是明显晴朗的天气，不仅是天空中的云量。满天云且正在下雨时，雨显著、晴朗反向显著；不要求阴云同时正向。阴云具体取中性还是负向，以及相应强度，尚未定案。

雨与雪分别保留可关联的场景。用户希望同一播单承接雨雪时，可以将两个场景绑定同一 Playlist。

雨雪混合可以同时支持雨和雪；预算主体仍是天气这一粗变量。具体强度、相邻项的支持与负向关系，以及雷暴、雾霾等现象如何映射到有限语义项，仍待讨论。

## 5. 活动观测、轨迹与显著度构建

活动通过观察与推断形成，当前主线为工作与娱乐两个有方向的语义项。Wandering（中文暂称“游移”）作为内部状态保留，不开放为可关联的语义项，当前无需单独构建其显著度。瞬时窗口状态需要合成为一段时间的活动语义。

用户不需要实时选择工作、娱乐或 Wandering。应用类别和标题规则由系统内置；具体识别范围尚待设计。

### 信息来源的取舍

| 信息来源 | 当前判断 |
| --- | --- |
| 前台应用与窗口 | 当前主要观察依据；应用身份、标题和前台历史形成活动轨迹。 |
| 非前台桌面窗口 | 曾探索维护整个窗口池，但未显示独立于前台轨迹的充分收益，当前不引入主线。 |
| 普通后台进程 | 价值不足；运行本身难以反映用户正在参与的活动。 |
| 窗口呈现状态 | 全屏、最大化等单独区分能力有限，当前不作为核心依据。 |
| 输入活动 | 区分度不足；无输入也可能是阅读、思考或观看。 |
| 媒体播放与音频 | 音频信息单独区分工作与娱乐的价值有限；是否支持独立的音频响应语义，列为后续开发评估问题，当前不纳入活动主线。 |
| 系统会话状态 | 锁屏、解锁等活动分类信号较弱，当前不作为重点。 |
| UI Automation、界面内容与画面识别 | 投入产出比低，并有越过产品观察边界的感觉，当前不展开。 |

浏览器扩展、网址等深入集成曾被提及，当前路线未采用。

### 已确认的构建流程

1. 根据前台应用身份和窗口标题识别当前片段的活动方向。
2. 将带时间的活动观察加入轨迹窗口。
3. 仅按时间远近加权，合成工作与娱乐的净方向值 \(r\)。
4. 对净方向应用有符号 S 形映射，得到两个语义项的显著度。

同一活动可以跨越多个应用窗口。具体应用类别、标题识别规则和轨迹的采集方式仍待设计。

### 时间远近权重

令 \(a\ge0\) 表示一条观察距现在的时间，当前采用：

\[
w(a)=2^{-(a/h)^3},
\qquad h>0
\]

它具有初期平缓、中段快速下降、末端短尾趋零的形状，满足 \(w(0)=1\)、\(w(h)=1/2\)。\(h\) 是历史观察权重减半的时间尺度；固定三次幂后，平台长度与下降宽度一起伸缩。

\(w\) 只与时间远近相关，不含活动类别、用户偏好、场景目录或连续段时长。

此前比较过线性、指数、幂律、高斯、余弦和五次平滑阶跃等衰减形式。当前选择三次幂指数；函数本身保留短尾，不要求在有限时刻精确归零。实际参与计算的观察范围另由已选定的 30 分钟轨迹窗口限定。

### 片段方向与净方向值

当前轨迹窗口仅保留最近 30 分钟的观察，离散公式以等长时间片为前提。以工作为正方向：

\[
x_k=
\begin{cases}
1,&\text{该片段属于工作}\\
-1,&\text{该片段属于娱乐}\\
0,&\text{其余}
\end{cases}
\]

令 \(a_k\) 为第 \(k\) 个片段的观察距现在的时间，\(w_k=w(a_k)\)，则：

\[
r_{\text{工作}}
=\frac{\sum_k w_kx_k}{\sum_k w_k},
\qquad
r_{\text{娱乐}}=-r_{\text{工作}}
\]

\(r_{\text{工作}}\in[-1,1]\) 表示时间加权后的净方向。工作与娱乐的反向证据在这一步合成；后续映射接收的是净方向。

其余片段取零，但仍保留在分母中。当前不只对已识别的工作与娱乐片段重新归一，也不为 Wandering 建立独立显著度。

### 有符号显著度映射

将第 3 节的正向映射扩展为：

\[
F_q(r)=
\operatorname{sgn}(r)
\frac{1-2^{-(|r|/q)^3}}
{1-2^{-(1/q)^3}},
\qquad r\in[-1,1],\ q>0
\]

取 \(\operatorname{sgn}(0)=0\)，得到：

\[
s_{\text{工作}}=F_q(r_{\text{工作}}),
\qquad
s_{\text{娱乐}}=F_q(r_{\text{娱乐}})
=-s_{\text{工作}}
\]

该构造保留零点和正负端点，满足 \(F_q(0)=0\)、\(F_q(1)=1\)、\(F_q(-1)=-1\)，并保持单调非减和反对称。它在活动语义中采用 \([-1,1]\) 的范围，不改变天气等其他变量可以超过通常显著参照值的方向。

时间权重与显著度映射虽共用三次幂指数结构，职责和参数不同：

| 函数 | 作用 | 参数含义 |
| --- | --- | --- |
| \(w(a)\) | 历史观察对当前判断的贡献 | \(h\)：时间远近尺度 |
| \(F_q(r)\) | 净活动方向到有符号显著度的换算 | \(q\)：感知阈值效应的曲线尺度 |

这两层的参数不绑定。\(h\)、\(q\) 的数值和校准方式尚未确定；感知曲线的阈值效应也不等于召回边界 \(b\)。

### 活动响应的校准参照

用户给出的当前满分要求是：此前工作占主导，经过 30 分钟连续明确娱乐后，娱乐显著度达到正向满值 \(s_{\text{娱乐}}=1\)。30 分钟用于满分锚定，不是工作与娱乐分数相等或刚刚改变排序的时刻，也不直接等于 \(h=30\) 分钟。

已确定暂时只保留最近 30 分钟的轨迹。连续娱乐覆盖整个窗口后，所有片段的娱乐方向值均为 1，任意正时间权重下都有 \(r_{\text{娱乐}}=1\)，因此现有映射直接得到 \(s_{\text{娱乐}}=1\)，无需增加满分饱和处理。

用户认为 30 分钟可能偏迟缓，但现阶段接受这个窗口长度。\(h\)、\(q\) 仍待校准，控制达到满分之前的变化过程；显著度会在连续活动过程中逐步变化。

“穿插”仅描述工作 → 短暂娱乐 → 工作这样的轨迹，是否改变主导方向由现有时间权重和净方向计算决定，不另建状态、连续性权重或独立时长阈值。

### 探索后未纳入当前方案的因素

维护完整桌面窗口池曾被讨论，但所举的应用关系主要可从前台轨迹获得；非前台窗口持续存在的独立区分价值有限，因此当前以应用身份、标题和前台历史为主。

连续段时长也曾作为额外权重 \(g(d)\) 探索。它会压低原有 \(r\) 并引入第二个活动建立过程。用户从“模糊的正确”出发，未看到它相对于仅按时间远近加权的充分收益，当前明确不引入连续性权重。

## 6. 待讨论

已确认活动构建主干、季节与时段的平台加 S 形过渡结构，以及降雨四档的显著度映射。以下仍未确定：

- **活动参数与采集：**30 分钟轨迹窗口及现有满分映射已确定，剩余为 \(h\)、\(q\) 的校准、应用类别与标题规则、采样周期。按实际时长计算、避免采样频率改变结果是助手提出的性质要求；不等长记录的时长口径仍待确认。
- **周期参数：**季节峰值日期、各平台与过渡区间的定位，四时段的峰值钟点与平台宽度，S 形过渡参数，以及邻项取中性或轻微负值的具体口径。夏季正向峰值前后各 10 天的平台宽度已确定。
- **天气数据对应：**将供应商的天气代码与雨雪量对应到已经确定的强度等级标尺，并落实其他天气强度的同类物理锚定；阴云中性／负向及其他相邻关系仍需具体表达。
- **跨变量衔接：**共同锚点的实际校准、各变量适用的数值范围、曲线确定后的正负显著边界。粗变量预算依据已确定为最高正向语义项显著度。
- **其他信息状态：**其他变量的信息缺失、无法判断与语义中性是否需要分别表示；是否需要统一独立的判断把握维度仍未定案。
- **开发问题：是否加入音频响应支持。** 当前不作为活动构建主线的一部分，后续评估是否接入相关音频信息并提供可关联的音频响应语义。
